# 0. PROPÓSITO DEL DOCUMENTO

Este archivo debe entregarse al agente de inteligencia artificial **junto con la imagen de referencia visual** que representa el estilo gráfico deseado para el videojuego.

La imagen adjunta debe ser tratada como la **referencia artística principal y obligatoria**.

No debe utilizarse únicamente como una inspiración general.

No debe reinterpretarse libremente la expresión “Pixel Art”.

No debe sustituirse su estética por otro estilo Pixel Art que resulte:

- más sencillo;
- más retro;
- más fácil de programar;
- más minimalista;
- más infantil;
- más genérico;
- más cercano a un prototipo.

El objetivo es que el videojuego sea **visualmente lo más fiel posible al lenguaje gráfico de la imagen de referencia**, adaptando escenarios, personajes, sistemas científicos, interfaz y animaciones a ese mismo estándar de calidad.

# FALLIDA

# 22. PIXEL ART AUTÉNTICO

No destruir el Pixel Art mediante filtros.

No usar:

- suavizado bilineal;
- blur generalizado;
- antialiasing excesivo;
- interpolación borrosa.

Utilizar:

```javascript
ctx.imageSmoothingEnabled = false;
```

y escalado:

```text
nearest-neighbor
```

Los píxeles deben permanecer definidos.

---

# 23. RESOLUCIÓN INTERNA

No utilizar una resolución tan baja que obligue a simplificar excesivamente los personajes y escenarios.

Como orientación:

```text
640 × 360
```

puede ser una resolución lógica adecuada para este proyecto.

También pueden utilizarse otras resoluciones si mejoran:

- rendimiento;
- fidelidad;
- composición;
- detalle.

La prioridad es conservar un Pixel Art verdadero y de alta calidad.

# 41. SI EL JUEGO ES UN ÚNICO HTML

La restricción de un solo archivo HTML **NO es una excusa para producir gráficos pobres**.

Si es necesario:

- generar spritesheets;
- generar tilesets;
- generar fondos;
- generar retratos;
- generar texturas Pixel Art;

y almacenarlos dentro del HTML mediante:

- Base64;
- Data URI;
- datos rasterizados internos;
- arrays gráficos;
- canvases precalculados.

El videojuego puede continuar siendo:

- autocontenido;
- offline;
- ejecutable localmente.

---

# 42. SIN RECURSOS EXTERNOS ≠ SIN ARTE

Esta regla es fundamental:

```text
SIN ASSETS EXTERNOS
≠
SIN ASSETS GRÁFICOS
```

Significa:

> los assets deben quedar incorporados dentro del juego.

No significa:

> reemplazar el arte por cuadrados y rectángulos simples.

---

# 43. NO SACRIFICAR EL ARTE POR FACILIDAD

No sacrifiques excesivamente la dirección artística por facilidad de programación.
